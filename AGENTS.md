# AGENTS.md

Context for AI agents working on abbydavid.com (Abby + David's personal site).

## What this is
- Static site on GitHub Pages (custom domain, `CNAME`). Plain HTML, CSS and vanilla JS. **No build step, no framework, no backend, no new dependencies.**
- Tone: quiet, editorial, personal, minimal but impactful. Not a startup, portfolio, wedding or SEO site. No ads, affiliate banners, popups, email capture, fake content or fake stats. No tech-buzzword branding.
- Palette: warm ivory paper, deep ink, teal accent, limited coral/gold/moss; dark mode is the same paper at night (warm ink, soft off-white, muted teal). The main site stays restrained. `/pets/` may be much more colorful.
- No visitor-facing links to github.com (project links to `*.github.io` are the projects' own hosted sites). Don't touch Pages/CNAME/repo infrastructure.
- Type: Newsreader (headings), Atkinson Hyperlegible Next (body), IBM Plex Mono (small metadata, sentence case, not uppercase). Self-hosted in `assets/fonts/` (OFL; see README). Avoid boxes, pills, shadows and floaty hover animations; use fine rules, figure captions ("Fig. N") and draw-in underlines.
- Theme: `theme.js` + inline head script, localStorage `abbydavid-theme`; dark values are duplicated in `styles.css` (media query and `[data-theme]`). The pet room (`.stage`) keeps its own local palette and is driven by St. Louis time/weather, not by the site theme.
- About: David's profile is written; Abby's is an open placeholder. Do not invent facts about Abby or David's work; the site is not affiliated with Bayer.
- Use root-relative paths (`/assets/...`) because of the custom domain.

## Workflow
- `main` is protected. Work on a branch, push, open a PR with `gh pr create -R revDWD/AbbyDavid.com -B main -H <branch>`. The user merges in the GitHub app (they are usually on an iPad).
- Commits end with: `Co-authored-by: Copilot <223556219+Copilot@users.noreply.github.com>`
- Check for a PR template before opening a PR.
- Keep replies short. Finish with a concise report: what was built, caveats, what the user must do.

## Layout
- `index.html`, `theme.js`, `styles.css` (shared design system and `.px` sprite classes, `.crew`), `404.html`, `projects/`, `pets/` (`index.html`, `pets.css`, `pets.js`), `assets/` (`og-image.png`, `apple-touch-icon.png`, `fonts/`, `pets/*.svg`).
- Projects: EcoTox ID and Oregon Trail DLE are featured. Public Move and Spirit Bomb Donations stay **off the homepage** but remain in the projects archive.
- Each page carries its own title, description, canonical, Open Graph and twitter tags (image 1200×630 with alt).

## Pets page (`/pets/`)
- A shared living room (rug, curtains, a framed specimen plate, a tiny covered wagon on the shelf as nods to Ecotox ID and Oregon Trail DLE) with four real pets: Jack (Chihuahua, black with white markings, **one eye**, never give him two), Albert (orange tabby with white), Elda (slender brown tabby), Svetlana (large brown tabby). Elda and Svetlana are sisters.
- **Do not invent** personalities, ages, histories, favorite things or pet relationships. Inter-pet moments stay neutral and affectionate.
- Wellbeing rules: no death, sickness, neglect, guilt, streaks, timers, currency, XP, levels, rarity or achievements. Secrets are never listed, counted or tracked. The scrapbook is charming, not collectible-game-like.
- Sprites: 8-frame SVG sheets (256×48 viewBox, 32×24 per frame; frames 0 stand, 1-2 walk, 3 sit, 4 lie, 5 happy, 6-7 blink; row 0 faces right, row 1 left). Generated by a script originally kept outside the repo (`/root/work/sprites2.py`, may no longer exist); edit the SVGs or regenerate.
- Real reference photos were never available as files. `PETS[].photo` in `pets.js` is ready for uploads (`assets/pets/photos/`).
- `pets.js` is one IIFE: storage, layout (unit `U` from stage width), autonomy (per-pet `nextAt`, weighted behaviors, long quiet gaps, max 2 pets moving), interactions, weather, season.
- Storage: key `abbydavid-pets-v1` (keep the `shetland` → `svetlana` migration, defensive load, capped numbers, Reset button); weather cache `abbydavid-weather-v1`.
- Weather: Open-Meteo forecast API for St. Louis (38.627, -90.199), fields `temperature_2m,weather_code,is_day,cloud_cover`, no key, no geolocation, 6s timeout, 30-min cache, 12-hour stale fallback. Failure must be silent apart from "Weather unavailable". Keep the CC BY 4.0 attribution. Time of day uses America/Chicago; seasons use the visitor's date.
- Accessibility: pet selection chips are real buttons with specific labels ("Select Jack", "Pet Albert"); the stage is `aria-hidden`; touch targets at least 44px; reduced motion disables autonomy; animation pauses when the page is hidden or off-screen. Never disable zoom.
- Sound was intentionally skipped. If added: muted by default, no autoplay, one toggle, remembered locally.
- iPad has its own composition (panel beside stage at wide/landscape, stacked with a 4-up chip row in portrait). Verified at 768×1024, 810×1080, 820×1180, 834×1194 and landscape, but only via Chromium emulation, not real Safari.

## CSS gotchas
- `.note` is the future notes-list class; the pets ambient line is `.ambient`.
- `[hidden]{display:none!important}` is deliberate.
- `text-transform: uppercase` makes Playwright `inner_text` uppercase; use `text_content`.

## Testing
- No test suite in the repo. Serve with `python3 -m http.server`, drive with Playwright (system Chrome at `/usr/bin/google-chrome`, `--no-sandbox`).
- The sandbox has no internet; mock `**/api.open-meteo.com/**` (include `access-control-allow-origin`). Route lambdas receive `(route, request)`, so use closures. `page.clock.install` fakes time.
- Check: no horizontal overflow, no console errors, no broken image paths, all four pets visible, keyboard use, weather success/failure/offline, reset, migration.
